  <name>Task 1: Create comprehensive contributing guide for gene configs</name>
  <files>
    configs/CONTRIBUTING.md
  </files>
  <action>
    Create `configs/CONTRIBUTING.md` — the primary contributing guide. This is the canonical location; the VitePress page will be a copy or near-copy.

    The guide must be written for clinical geneticists who may not be software developers. Use clear, accessible language. Structure:

    **1. Introduction**
    - What gene configs are and why they matter (curated per-gene settings for carrier frequency calculation)
    - How configs improve the calculator (auto-apply recommended filters, penetrance, variant exclusions)
    - Who should contribute (anyone with domain knowledge of a specific gene's pathogenic variant landscape)

    **2. Quick Start**
    - Copy an existing config (e.g., `configs/genes/HEXA.json`) as a template
    - Edit the fields for your gene
    - Submit a pull request
    - CI will validate your config automatically

    **3. Config File Location**
    - Files go in `configs/genes/` directory
    - Filename: `{GENE_SYMBOL}.json` (uppercase, e.g., `PAH.json`)
    - One file per gene

    **4. Schema Reference — Field by Field**
    Document every field with: name, type, required/optional, description, example value.

    Top-level fields:
    - `schemaVersion`: Always "1.0" (required)
    - `geneSymbol`: HGNC gene symbol, uppercase (required, 1-20 chars)
    - `displayName`: Full gene name (optional, for display)
    - `omimGeneId`: OMIM *Gene* entry number, 6 digits (optional). NOTE: This is the gene entry, NOT the disease entry.
    - `inheritance`: "AR", "XL", or "AD" (optional)
    - `profiles`: Array of condition profiles (required, at least 1)

    Profile fields:
    - `profileId`: Unique identifier within this config (required)
    - `displayName`: Human-readable condition name (required)
    - `isDefault`: Whether this is the default profile (required boolean). EXACTLY ONE profile must be default.
    - `disease`: Disease identifier object (required)
    - `penetrance`: Disease penetrance 0.0-1.0 (optional, defaults to 1.0 = fully penetrant)
    - `filterOverrides`: Recommended variant filter settings (optional)
    - `variantExclusions`: Array of variant IDs to exclude (optional)
    - `notes`: Free-text notes about this condition profile (optional)
    - `references`: Array of URLs to supporting literature (optional, must be valid URLs)

    Disease identifier fields:
    - `omimId`: OMIM *Phenotype* MIM number, 6 digits (optional)
    - `mondoId`: MONDO identifier, format MONDO:XXXXXXX (optional)
    - `name`: Disease name (required)
    - IMPORTANT: At least one of `omimId` or `mondoId` is required.

    Filter override fields (all optional):
    - `lofHcEnabled`: Include Loss-of-Function High Confidence variants (boolean)
    - `missenseEnabled`: Include missense variants (boolean)
    - `clinvarEnabled`: Include ClinVar Pathogenic/Likely Pathogenic variants (boolean)
    - `clinvarStarThreshold`: Minimum ClinVar review stars 0-4 (integer)
    - `clinvarIncludeConflicting`: Include conflicting classifications with majority P/LP (boolean)
    - `clinvarConflictingThreshold`: Minimum P/LP percentage for conflicting variants 50-100 (integer)

    **5. OMIM Gene ID vs OMIM Phenotype ID**
    - Clearly explain the distinction with a table:
      | Field | OMIM Entry Type | Example (CFTR) | Where to Find |
      |-------|----------------|----------------|---------------|
      | `omimGeneId` | Gene entry (asterisk *) | 602421 | omim.org gene page |
      | `disease.omimId` | Phenotype entry (hash #) | 219700 | omim.org disease page |
    - Link to OMIM search: https://omim.org/
    - Common mistake: putting the gene entry number in the disease omimId field

    **6. Complete Example**
    - Show a complete, well-commented config file for a hypothetical gene (or reference HEXA.json as the simplest real example)
    - Show a multi-profile example (reference CFTR.json)

    **7. Finding Penetrance Values**
    - Where to look: GeneReviews (ncbi.nlm.nih.gov/books/NBK1116/), OMIM, published literature
    - Use 1.0 (fully penetrant) if unsure — this is the conservative default
    - For reduced penetrance conditions, cite the source in references

    **8. Finding Disease Identifiers**
    - OMIM: https://omim.org/ — search for the disease (not the gene)
    - MONDO: https://monarchinitiative.org/ — search for the disease
    - At least one identifier is required; both are preferred

    **9. Submitting Your Config**
    - Fork the repository
    - Create your config file in `configs/genes/`
    - Open a pull request targeting `main`
    - CI will automatically validate your config against the schema
    - A maintainer will review the clinical content
    - Wait for approval and merge

    **10. What CI Validates**
    - JSON syntax
    - Schema compliance (all required fields present, correct types, value ranges)
    - Exactly one default profile
    - At least one disease identifier per profile
    - OMIM/MONDO ID format (6 digits / MONDO:7 digits)
    - Filename matches geneSymbol

    **11. FAQ**
    - "Can I add a gene that already has a config?" — Yes, open an issue to discuss updates
    - "What if I don't know the penetrance?" — Use 1.0 (fully penetrant), add a note
    - "Can I add multiple conditions for one gene?" — Yes, add multiple profiles (see CFTR example)
    - "What variant exclusions should I add?" — Known benign variants with high allele frequency that would inflate carrier frequency calculations
    - "My config fails CI validation — what do I do?" — Check the error messages, they point to the exact field and issue

    **12. Resources**
    - OMIM: https://omim.org/
    - MONDO / Monarch Initiative: https://monarchinitiative.org/
    - GeneReviews: https://www.ncbi.nlm.nih.gov/books/NBK1116/
    - HGNC Gene Names: https://www.genenames.org/
    - gnomAD: https://gnomad.broadinstitute.org/
