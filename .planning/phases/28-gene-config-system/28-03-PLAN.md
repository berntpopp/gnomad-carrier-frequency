    **apps/web/vite.config.ts** — Add Vite alias for gene config JSON imports:
    - Add a new alias entry in the `resolve.alias` array: `{ find: '~gene-configs', replacement: fileURLToPath(new URL('../../configs/genes', import.meta.url)) }`.
    - Place it before the `@` alias (order matters — more specific aliases first).
    - The existing `@gnomad-cf/core` regex alias already handles core imports; `~gene-configs` handles the JSON files in the repo-root `configs/` directory.

    **apps/web/src/main.ts** — Register seed gene configs at app startup:
    - Import `registerGeneConfig` from `@gnomad-cf/core/gene-config`.
    - Import the three seed config JSON files using the Vite alias:
      ```
      import cftrConfig from '~gene-configs/CFTR.json'
      import hexaConfig from '~gene-configs/HEXA.json'
      import gjb2Config from '~gene-configs/GJB2.json'
      ```
    - Before `app.mount('#app')`, call `registerGeneConfig` for each config. Use type assertion `as any` since JSON imports lack the refined Zod type — CI validates correctness.
    - Add a comment: `// Register seed gene configs (validated by CI workflow)`

    **apps/web/src/composables/useGeneConfig.ts** — New composable (singleton pattern):
    - Use module-level `ref()` state (matches useGeneSearch singleton pattern, NOT a Pinia persisted store — active config should NOT persist across sessions):
      - `activeGeneConfig: Ref<GeneConfig | null>` — the loaded config
      - `activeProfile: Ref<ConditionProfile | null>` — the active condition profile
      - `configLoaded: Ref<boolean>` — whether a config is active
    - Import `loadGeneConfig` from `@gnomad-cf/core/gene-config` and types `GeneConfig`, `ConditionProfile`.
    - Import `useGeneSearch` to access `selectedGene`.
    - Import `useFilterStore` and `useCalcStore` from stores.
    - The composable function `useGeneConfig()` returns reactive state + actions:
      - `watch(selectedGene, async (gene) => { ... }, { immediate: true })` handler:
        - If gene is null or undefined: reset all state (activeGeneConfig = null, activeProfile = null, configLoaded = false), call `filterStore.resetToFactoryDefaults()` and `calcStore.resetToFactoryDefaults()`, return.
        - Call `const config = await loadGeneConfig(gene.symbol)`.
        - If config is null: reset all state AND reset stores to factory defaults (prevents state bleed from previous config gene), return.
        - If config found: set activeGeneConfig, find default profile (`config.profiles.find(p => p.isDefault)!`), set activeProfile, set configLoaded = true.
        - Apply filter overrides from default profile: if `profile.filterOverrides` exists, call `filterStore.setDefaults(profile.filterOverrides)` (partial merge — only overrides specified fields).
        - Apply penetrance from default profile: if `profile.penetrance !== undefined`, call `calcStore.setPenetrance(profile.penetrance)`.
      - CRITICAL: When switching from a config gene to a non-config gene, ALWAYS reset to factory defaults. This prevents Pitfall 4 (filter state bleed).
      - `selectProfile(profileId: string)`: Find profile in activeGeneConfig, set activeProfile, apply its filterOverrides and penetrance to stores. Reset stores to factory defaults first, then apply the new profile's overrides (clean slate for each profile switch).
      - `resetConfig()`: Reset stores to factory defaults, clear all reactive state (activeGeneConfig = null, activeProfile = null, configLoaded = false).
      - `availableProfiles`: computed returning `activeGeneConfig.value?.profiles ?? []`.
      - Return: `{ activeGeneConfig, activeProfile, configLoaded, selectProfile, resetConfig, availableProfiles }`.

    **apps/web/src/composables/index.ts** — Add re-export:
    - Add `export { useGeneConfig } from './useGeneConfig'` to the barrel file.

    IMPORTANT: The useGeneConfig composable must be called AFTER Pinia is initialized (it accesses stores). The `watch` with `immediate: true` will fire on first use. The composable should be initialized from a component (e.g., App.vue or the wizard component), not from main.ts directly. Actually — since it uses `watch` on `selectedGene` which is module-level, it can be initialized lazily when FilterPanel first renders.

    IMPORTANT: Do NOT make the gene config state a Pinia persisted store. Module-level refs are correct — config applies per-session based on the selected gene, not persisted.

    NOTE: Also add the `~gene-configs` path to `apps/web/tsconfig.json` if a separate tsconfig exists with path aliases, so TypeScript resolves the JSON imports correctly. Check `apps/web/tsconfig.json` (or `tsconfig.app.json`) for existing `paths` config. If it uses the core project reference, add `"~gene-configs/*": ["../../configs/genes/*"]` to paths.

    Update `FilterPanel.vue` to show a "Gene config loaded" indicator and a profile selector dropdown.

    **Import useGeneConfig:**
    - In the `<script setup>` section, import `useGeneConfig` from `@/composables/useGeneConfig`.
    - Destructure: `const { configLoaded, activeGeneConfig, activeProfile, availableProfiles, selectProfile, resetConfig } = useGeneConfig()`.

    **Gene config indicator chip:**
    - In the `<template>`, inside the expansion panel title `<div class="d-flex align-center flex-wrap ga-2">`, after the `<FilterChips>` component, add:
      ```vue
      <v-chip
        v-if="configLoaded"
        color="info"
        size="x-small"
        prepend-icon="mdi-dna"
        closable
        @click:close="resetConfig"
      >
        Gene config loaded
      </v-chip>
      ```
    - This follows the existing `v-chip` pattern used in `FilterChips.vue` and `FrequencyResults.vue`.
    - The `closable` prop with `@click:close="resetConfig"` allows users to dismiss the config and return to factory defaults.

    **Profile selector dropdown (for multi-profile genes like CFTR):**
    - Inside the expansion panel text area (`<v-expansion-panel-text>`), before the filter switches (before the first `<v-row dense>`), add a conditional profile selector:
      ```vue
      <v-select
        v-if="configLoaded && availableProfiles.length > 1"
        :model-value="activeProfile?.profileId"
        :items="availableProfiles.map(p => ({ title: p.displayName, value: p.profileId }))"
        label="Condition profile"
        density="compact"
        variant="outlined"
        hide-details
        class="mb-3"
        @update:model-value="selectProfile($event)"
      />
      ```
    - This only shows when there are multiple profiles (CFTR has 2, HEXA and GJB2 have 1).
    - When user selects a different profile, `selectProfile` applies that profile's overrides.

    **availableProfiles reactivity note:** The `availableProfiles` from useGeneConfig is a computed. The `v-if` guards ensure the selector only renders when a multi-profile config is active. The `:items` mapping must happen inline in the template since `availableProfiles` is reactive.

    NOTE: Clinical text output does NOT mention which gene config profile was used — the user decision says "text reports numbers only." No changes to text generation are needed.
