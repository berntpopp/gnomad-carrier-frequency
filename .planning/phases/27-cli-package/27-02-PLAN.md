1. Create `packages/cli/src/utils/retry.ts`:

Implement `withRetry<T>(fn, opts)` with:
- `retries`: max retry count (default 3)
- `baseDelayMs`: initial delay (default 1000)
- `maxDelayMs`: maximum delay cap (default 16000)
- Exponential backoff: `baseDelayMs * 2^attempt`
- Random jitter: add `Math.random() * 500` to avoid thundering herd
- Cap delay at `maxDelayMs`
- On 429 status (rate limited): always retry (don't count as terminal)
- On 4xx (not 429): throw immediately (terminal error)
- On 5xx or network error: retry up to `retries` times
- Return the result on first success

The function should detect HTTP status from the error. If the error is an Error with message containing a status code (e.g., "GraphQL request failed: 429"), parse it. The core client's `executeGraphQLQuery` throws `new Error(\`GraphQL request failed: ${response.status}\`)` on non-ok responses, so check for "429" and "4" prefix in the error message.

Export the function and the options type.

2. Create `packages/cli/src/utils/gene-query.ts`:

This is the heart of the CLI. It orchestrates: fetch gene data -> filter variants -> aggregate frequencies -> return structured result.

IMPORTANT: Import `QueryResult`, `QueryOptions`, and `VariantDetail` from `../types.js` (created in Plan 01). Do NOT redefine these types inline.

```typescript

```

Export `async function queryGene(gene: string, opts: QueryOptions): Promise<QueryResult>`:

1. Call `executeGraphQLQuery` from `@gnomad-cf/core/client` with `GENE_VARIANTS_QUERY` from `@gnomad-cf/core/queries`, passing:
   - `geneSymbol: gene.toUpperCase()`
   - `dataset: getDatasetId(opts.version)` from `@gnomad-cf/core/config`
   - `referenceGenome: getReferenceGenome(opts.version)` from `@gnomad-cf/core/config`
2. Wrap in `withRetry()` from `./retry.js`
3. Check for GraphQL errors: if `response.errors?.length`, throw with joined messages
4. Check gene exists: if `!response.data?.gene`, throw `Gene "${gene}" not found in gnomAD`
5. Extract `variants` and `clinvar_variants` from response
6. Call `filterPathogenicVariantsConfigurable(variants, clinvar_variants, opts.filterConfig, new Map())` from `@gnomad-cf/core/filters`
7. Call `aggregatePopulationFrequenciesWithConfig(pathogenic, opts.version, opts.calcConfig)` from `@gnomad-cf/core/calculations`
8. Call `buildPopulationFrequencies(aggregated, globalCF, opts.version)` from `@gnomad-cf/core/calculations`
9. If `opts.population` is set, filter the population results to only that code
10. Compute global stats:
    - globalSumAF: sum of all per-variant (exome.ac + genome.ac) / (exome.an + genome.an) across filtered variants
    - globalAlleleCount: sum of (exome.ac + genome.ac) across filtered variants
    - globalAlleleNumber: max of (exome.an + genome.an) across filtered variants
    - globalCarrierFrequency: compute using same formula as aggregatePopulationFrequenciesWithConfig but for global
    - geneticPrevalence: globalSumAF^2
    - bayesianPrevalence: geneticPrevalence * opts.calcConfig.penetrance
11. Return the QueryResult

Also export `async function searchGenes(query: string, version?: GnomadVersion): Promise<Array<{ symbol: string, ensembl_id: string }>>`:
- Call `executeGraphQLQuery` with `GENE_SEARCH_QUERY` from `@gnomad-cf/core/queries`
- Pass `query` and `referenceGenome` from `getReferenceGenome(version)`
- Return the gene_search results array
- Wrap in withRetry for resilience

The response type for gene search is `{ gene_search: Array<{ ensembl_id: string, symbol: string }> }`. Define this locally or import `GeneSearchResponse` from `@gnomad-cf/core/queries`.

The response type for gene variants is `GeneVariantsResponse` from `@gnomad-cf/core/queries`.

IMPORTANT: Don't reimplement any calculation logic. Import everything from @gnomad-cf/core subpaths.
