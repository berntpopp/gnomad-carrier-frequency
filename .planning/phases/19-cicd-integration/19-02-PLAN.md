    **Note on parallel execution with Plan 19-01:** This plan is Wave 1 alongside Plan 19-01. The two plans modify entirely different files (no conflict).     **CONTEXT.md deviation — [skip ci]:** CONTEXT.md states "Screenshot auto-commit uses [skip ci] to prevent redundant CI checks on image-only changes, but allows deploy workflow to trigger (cascade deploy for fresh docs)." Research (19-RESEARCH.md, Pitfall 2) proved this is technically impossible: `[skip ci]` in a commit message skips ALL push-triggered workflows at the GitHub event level, including deploy.yml. There is no mechanism to selectively skip CI but allow deploy. Therefore, this plan intentionally omits `[skip ci]` from the auto-commit message. The cascade deploy is achieved via PAT-based push (which triggers deploy.yml), and infinite loop prevention is handled by `paths-ignore` + actor check (which prevents screenshots.yml from re-triggering). This is documented here and should also be noted when updating CONTEXT.md (see below).

    **CONTEXT.md update required:** After creating screenshots.yml, update the CONTEXT.md `<decisions>` section line about `[skip ci]`. Change:
    "Screenshot auto-commit uses [skip ci] to prevent redundant CI checks on image-only changes, but allows deploy workflow to trigger (cascade deploy for fresh docs)"
    To:
    "Screenshot auto-commit does NOT use [skip ci] — research proved [skip ci] skips ALL push-triggered workflows including deploy (technically impossible to skip CI but allow deploy). Instead, cascade deploy is achieved via PAT push + paths-ignore/actor-check for infinite loop prevention."

    The workflow must implement these behaviors:
    1. **Trigger:** Push to `main` only, path-filtered to UI files (`src/**`, `public/**`, `index.html`, `package.json`, `bun.lockb`), with `paths-ignore` for `docs/public/screenshots/**` to prevent self-retriggering
    2. **Extra loop prevention:** Job-level condition `if: github.actor != 'github-actions[bot]'` as a safety net in case paths-ignore is insufficient
    3. **Build:** Install bun, install deps, cache Playwright Chromium, build the app
    4. **Screenshots:** Run `bunx tsx scripts/generate-screenshots.ts` with explicit `BASE_URL` env var
    5. **Auto-commit:** If screenshots changed (detected by `git diff --quiet docs/public/screenshots/`), commit with `github-actions[bot]` author and push. Commit message: `chore: update screenshots` (NO `[skip ci]` — see deviation note above)
    6. **Cascade deploy:** Use `secrets.SCREENSHOTS_TOKEN || github.token` for checkout token. If PAT is available, the push triggers deploy.yml. If not, falls back gracefully to GITHUB_TOKEN (no cascade, but no failure either)
    7. **Failure alerting:** On failure, create a GitHub issue with the `screenshots` label. Create the label first if it doesn't exist (`gh label create ... || true`)

    Playwright browser caching pattern:
    - Cache path: `~/.cache/ms-playwright`
    - Cache key: `playwright-${{ runner.os }}-${{ hashFiles('bun.lockb') }}`
    - On cache miss: `bunx playwright install chromium --with-deps` (full install)
    - On cache hit: `bunx playwright install-deps chromium` (system deps only)

    The screenshot script starts its own dev server internally (see `scripts/generate-screenshots.ts` startDevServer function), so the workflow does NOT need to start a separate server. But the script does `bun run build` is NOT needed for the screenshot script — it uses the dev server. HOWEVER, the screenshot script calls `npm run dev` internally. Since we're standardizing on bun, the script spawns `npm run dev` which resolves to `vite` regardless of package manager. This is fine — vite is the actual executable, and npm/bun are just wrappers.     Actually, looking more carefully: The screenshots workflow should NOT do `bun run build` — the screenshot script runs a DEV server, not a preview server. The script does `spawn('npm', ['run', 'dev'], ...)` which starts Vite dev server. So the workflow steps should be: install deps -> install Playwright -> run screenshot script. No separate build step needed.

    Full workflow content:

    ```yaml
    name: Update Screenshots

    on:
      push:
        branches: ['main']
        paths:
          - 'src/**'
          - 'public/**'
          - 'index.html'
          - 'package.json'
          - 'bun.lockb'
        paths-ignore:
          - 'docs/public/screenshots/**'

    jobs:
      update-screenshots:
        # Extra safety: don't run if triggered by bot's own commits
        if: github.actor != 'github-actions[bot]'
        runs-on: ubuntu-latest
        permissions:
          contents: write
          issues: write
        steps:
          - uses: actions/checkout@v5
            with:
              # Use PAT for cascade deploy (screenshot commit triggers deploy.yml)
              # Falls back to GITHUB_TOKEN if PAT not configured (no cascade, but no failure)
              token: ${{ secrets.SCREENSHOTS_TOKEN || github.token }}

          - uses: oven-sh/setup-bun@v2

          - name: Install dependencies
            run: bun install --frozen-lockfile

          - name: Cache Playwright browsers
            uses: actions/cache@v4
            id: playwright-cache
            with:
              path: ~/.cache/ms-playwright
              key: playwright-${{ runner.os }}-${{ hashFiles('bun.lockb') }}
              restore-keys: |
                playwright-${{ runner.os }}-

          - name: Install Playwright Chromium
            if: steps.playwright-cache.outputs.cache-hit != 'true'
            run: bunx playwright install chromium --with-deps

          - name: Install Playwright system deps only
            if: steps.playwright-cache.outputs.cache-hit == 'true'
            run: bunx playwright install-deps chromium

          - name: Generate screenshots
            run: bunx tsx scripts/generate-screenshots.ts
            env:
              BASE_URL: 'http://localhost:5173/'

          - name: Check for screenshot changes
            id: check_changes
            run: |
              git diff --quiet docs/public/screenshots/ && echo "changed=false" >> $GITHUB_OUTPUT || echo "changed=true" >> $GITHUB_OUTPUT

          - name: Commit and push updated screenshots
            if: steps.check_changes.outputs.changed == 'true'
            run: |
              git config --local user.email "github-actions[bot]@users.noreply.github.com"
              git config --local user.name "github-actions[bot]"
              git add docs/public/screenshots/
              git commit -m "chore: update screenshots"
              git push

          - name: Ensure screenshots label exists
            if: failure()
            run: |
              gh label create screenshots --color "0075ca" --description "Screenshot-related issues" --repo ${{ github.repository }} 2>/dev/null || true
            env:
              GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

          - name: Create issue on failure
            if: failure()
            run: |
              gh issue create \
                --title "Screenshot workflow failed on $(date -u +'%Y-%m-%d')" \
                --body "## Screenshot Workflow Failed

              The automated screenshot update workflow failed.

              **Run:** [${{ github.run_id }}](${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }})
              **Commit:** ${{ github.sha }}
              **Branch:** ${{ github.ref_name }}

              Please investigate and re-run manually if needed." \
                --label "screenshots" \
                --repo ${{ github.repository }}
            env:
              GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    ```

    Note on infinite loop prevention (two layers):
    1. `paths-ignore: ['docs/public/screenshots/**']` — screenshot auto-commits only touch files in this path, so they don't match the trigger paths
    2. `if: github.actor != 'github-actions[bot]'` — even if paths somehow matched, the bot actor check prevents re-triggering
