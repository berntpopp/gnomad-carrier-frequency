**useGeneSearch.ts** -- Step 1: Promote core state to module-level (singleton pattern):

Currently `searchTerm`, `debouncedTerm`, and `selectedGene` are declared INSIDE `useGeneSearch()`, creating separate instances per caller. This MUST be fixed — promote them to module-level (outside the function), matching the existing pattern used by `sharedGeneConstraint` and `sharedConstraintLoading` in the same file, and consistent with how `useWizard.ts` declares its `state` at module-level.

Move these three lines from inside `useGeneSearch()` to module-level (next to the existing `sharedGeneConstraint` and `sharedConstraintLoading`):
```typescript
const searchTerm = ref('');
const debouncedTerm = ref('');
const selectedGene = ref<GeneSearchResult | null>(null);
```

This ensures all callers of `useGeneSearch()` — including WelcomeCard.vue and GeneSearch.vue — share the same reactive state.

**useGeneSearch.ts** -- Step 2: Add `prefillGene` function:

Add a new exported function `prefillGene(symbol: string)` that:
1. Sets `debouncedTerm.value = symbol.trim().toUpperCase()` (bypasses debounce, triggers villus query immediately).
2. Sets `searchTerm.value = symbol` (keeps raw input in sync).
3. Creates a one-shot watcher on `data` (the villus query result). When results arrive and contain a match for the symbol, calls `selectGene(results[0])` and stops the watcher via `stop()`.
4. Returns a Promise that resolves when the gene is selected (or rejects on timeout after ~5s).
5. Add `prefillGene` to the `UseGeneSearchReturn` interface and the return object.

**GeneSearch.vue** -- Step 3: Add display-only watcher for external selectedGene changes:

Add `watch(selectedGene, (gene) => { ... })` that syncs the local `model` ref and `searchInput` ref when `selectedGene` changes externally (e.g., from prefillGene called by WelcomeCard).
- When `selectedGene` becomes non-null: set `model.value = gene` and `searchInput.value = gene.symbol`.
- When `selectedGene` becomes null: set `model.value = null` and `searchInput.value = ''`.
- This watcher MUST NOT emit 'select'. It is display-only. The `selectGene()` call inside `prefillGene` already handles all state mutations (setting `selectedGene`, fetching constraint data). The GeneSearch watcher just keeps the v-autocomplete's local model in sync with the shared singleton state. Emitting 'select' here would create a double-invocation path through `selectGene` and cause duplicate constraint fetches.

**StepGene.vue** -- Step 4: Wire WelcomeCard and handle gene selection from prefill:

1. Import `WelcomeCard` from `@/components/WelcomeCard.vue`.
2. Place `<WelcomeCard />` at the top of the template, BEFORE the `<h2>Select Gene</h2>` heading.
3. The WelcomeCard handles its own visibility via `appStore.shouldShowOnboarding` — StepGene just renders it.
4. StepGene already watches `state.gene` from `useWizard()` for downstream effects. When `prefillGene` calls `selectGene`, the GeneSearch `@select` emit does NOT fire (watcher is display-only), but StepGene needs to set `state.gene`. **Solution**: In StepGene, add a `watch` on `selectedGene` (from useGeneSearch) that sets `state.gene = selectedGene.value` when it changes to non-null. This single watcher handles both manual selection via GeneSearch's `@select` emit AND programmatic selection via `prefillGene`. Remove the `@select` handler on `<GeneSearch>` and use this watcher as the single code path.
