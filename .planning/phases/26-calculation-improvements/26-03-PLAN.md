         calcConfig: CalcConfig
       ): Map<string, { carrierFrequency: number | null; sumAF: number; totalAC: number; maxAN: number; geneticPrevalence: number | null }>

       Implementation logic for EACH population:
       - Always compute sumAF (sum of per-variant AFs) for that population -- needed for prevalence regardless of formula
       - If calcConfig.useHomExclusion is TRUE:
         - For each variant, compute VCR using population-level ac, an, ac_hom
         - Access ac_hom with explicit null check on the exome/genome wrapper:
           `(variant.exome !== null ? variant.exome.ac_hom : 0)` -- NOT `variant.exome?.ac_hom ?? 0`
           The null-guard is on the exome/genome wrapper object (which CAN be null for some variants),
           NOT on ac_hom itself (which is always present as a number when the wrapper exists).
         - Aggregate VCRs via GCR -> this is the population carrier frequency
       - If calcConfig.useHomExclusion is FALSE:
         - If calcConfig.useHWEFormula is TRUE: carrier freq = calculateHWECarrierFrequency([sumAF]) -- note: pass sumAF as single element since it's already the population total q
         - If calcConfig.useHWEFormula is FALSE: carrier freq = 2 * sumAF (simplified)
       - If calcConfig.useHomExclusion is TRUE AND calcConfig.useHWEFormula has a setting:
         - GCR is always used when hom exclusion is ON. The HWE toggle only affects the non-hom-exclusion path.
         - HOWEVER, per research recommendation, these are INDEPENDENT AXES. When hom exclusion is ON, GCR is used for carrier rate. The HWE toggle is conceptually about interpretation of the q value, but since GCR bypasses the q-based approach entirely, HWE toggle has no effect when hom exclusion is ON. This is expected behavior.
       - Genetic prevalence: always q^2 where q = sumAF for that population

       REMOVE the old `aggregatePopulationFrequencies` function (the one without CalcConfig param). After this plan, nothing calls it -- `aggregatePopulationFrequenciesWithConfig` replaces it entirely.        When calcConfig is provided and hom exclusion is ON, use the carrier frequencies from aggregation (already computed with GCR). When not provided or hom exclusion OFF, use existing 2*sumAF logic.
