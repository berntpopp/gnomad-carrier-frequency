  <behavior>
    ## Variant Filters (TEST-05)

    Test the variant filtering functions that were extracted to `packages/core/src/filters/`.
    Read the actual exported functions from the filters module to understand exact signatures.
    The main function is likely `filterPathogenicVariantsConfigurable` (or similar name after extraction).

    Test cases for LoF HC filtering:
    - Variant with lof="HC" and canonical=true -> INCLUDED
    - Variant with lof="LC" -> EXCLUDED (only HC passes)
    - Variant with lof="HC" but canonical=false -> EXCLUDED (must be canonical transcript)
    - Variant with lof=null -> EXCLUDED from LoF filter
    - When lofHcEnabled=false -> no LoF variants included regardless

    Test cases for ClinVar Pathogenic filtering:
    - Variant with clinical_significance="Pathogenic" and gold_stars >= threshold -> INCLUDED
    - Variant with clinical_significance="Likely pathogenic" and gold_stars >= threshold -> INCLUDED
    - Variant with clinical_significance="Pathogenic" but gold_stars < threshold -> EXCLUDED
    - Variant with clinical_significance="Benign" -> EXCLUDED
    - When clinvarEnabled=false -> no ClinVar filter applied

    Test cases for missense filtering:
    - Variant with consequence_terms containing "missense_variant" -> INCLUDED when missenseEnabled=true
    - Same variant -> EXCLUDED when missenseEnabled=false

    Test cases for conflicting classifications:
    - Variant with "Conflicting interpretations" and majority P/LP submissions above threshold -> INCLUDED when clinvarIncludeConflicting=true
    - Same variant below threshold -> EXCLUDED
    - When clinvarIncludeConflicting=false -> conflicting variants excluded regardless

    Test cases for filter combinations:
    - Variant qualifies as both LoF HC AND ClinVar P/LP -> included once (no double-counting)
    - No filters enabled -> empty result
    - All filters enabled -> union of qualifying variants

    Edge cases:
    - Empty variant array -> empty result
    - Variant with null transcript_consequence -> handled gracefully
    - Variant with null exome and null genome -> handled gracefully

    ## Template Renderer (TEST-06)

    Test the template rendering functions extracted to `packages/core/src/templates/`.
    Read the actual exported functions to understand exact signatures.
    The main function is likely `renderTemplate` or similar.

    Test cases for variable substitution:
    - Template "{{gene}} carrier frequency" with { gene: "CFTR" } -> "CFTR carrier frequency"
    - Multiple variables in one template -> all replaced
    - Unknown variable -> left as-is or removed (match actual behavior)
    - Empty template -> empty string

    Test cases for perspective:
    - Template for "affected" perspective renders different text than "carrier"
    - Template for "family" perspective renders appropriate language

    Test cases for German gender-inclusive language:
    - Template with gender placeholder using "*" style -> "Patient*in"
    - Template with gender placeholder using ":" style -> "Patient:in"
    - Template with gender placeholder using "/" style -> "Patient/in"
    - Default style applied when not specified

    Test cases for section enabling/disabling:
    - Enabled section -> rendered in output
    - Disabled section -> omitted from output

    Edge cases:
    - Null/undefined carrier frequency -> appropriate fallback text
    - Very large frequency value -> formatted correctly
    - Very small frequency value -> formatted correctly
    - Missing required template variables -> handled gracefully
