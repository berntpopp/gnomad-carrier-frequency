<task type="auto">
  <name>Task 2: Create GitHub Actions tests workflow</name>
  <files>
    .github/workflows/tests.yml
  </files>
  <action>
    Create `.github/workflows/tests.yml` — a SEPARATE workflow from the existing `ci.yml` (which handles lint, typecheck, build). Per CONTEXT.md: "Scope: tests + coverage only — lint and typecheck are separate concerns."

    ```yaml
    name: Tests

    on:
      push:
        branches: ['*']
      pull_request:
        branches: ['main']

    jobs:
      test:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v5

          - uses: oven-sh/setup-bun@v2

          - name: Install dependencies
            run: bun install --frozen-lockfile

          - name: Build core (required by CLI and web tests)
            run: bun run --filter @gnomad-cf/core build

          - name: Run core tests with coverage
            run: bun run --filter @gnomad-cf/core test -- --coverage

          - name: Run CLI tests with coverage
            run: bun run --filter @gnomad-cf/cli test -- --coverage

          - name: Run web component tests with coverage
            run: bun run --filter gnomad-cf-web test -- --coverage

          # E2E tests only on PRs to main (not every push)
          - name: Install Playwright browsers
            if: github.event_name == 'pull_request' && github.base_ref == 'main'
            run: npx playwright install --with-deps chromium

          - name: Build web app for E2E
            if: github.event_name == 'pull_request' && github.base_ref == 'main'
            run: bun run --filter @gnomad-cf/core build && bun run --filter gnomad-cf-web build

          - name: Run E2E tests
            if: github.event_name == 'pull_request' && github.base_ref == 'main'
            run: npx playwright test

          - name: Coverage summary
            if: always()
            run: |
              echo "## Coverage Targets (warn-only)"
              echo "- Core: 90%+ target"
              echo "- CLI: 80%+ target"
              echo "- Web: 40%+ target"
              echo ""
              echo "Coverage percentages are printed above in each test step output."
              echo "These thresholds are advisory — the build does not fail on low coverage."
    ```

    Key decisions from CONTEXT.md:
    - Single job, sequential steps (core -> CLI -> web -> E2E)
    - E2E only on PRs to main (`github.event_name == 'pull_request' && github.base_ref == 'main'`)
    - Coverage: console output only — no PR comment bots, no badges
    - Warn-only thresholds (thresholds set to 0 in vitest configs, targets documented in comments)
    - Build core first — CLI tests and web tests may import from `@gnomad-cf/core` which needs to be built

    Note: The E2E step uses `bun run --filter gnomad-cf-web build` to create a production build. The playwright config uses `bun run dev` for the webServer — but in CI, we should consider whether to use `bun run preview` (serves the built app) instead of `bun run dev` (starts Vite dev server). Check if the playwright config's webServer.command is appropriate for CI.

    If using dev server in CI is fine (it should be — Playwright's webServer config handles startup), keep `bun run dev`. If using preview is better for CI (faster, closer to production), update playwright.config.ts to detect CI:
    ```typescript
    webServer: {
      command: process.env.CI ? 'bun run preview' : 'bun run dev',
      url: process.env.CI ? 'http://localhost:4173' : 'http://localhost:5173',
      ...
    }
    ```
    And update `baseURL` similarly. This is at your discretion — either approach works.
