<objective>
Create the web data layer for subcontinental populations: a Pinia session store for caching per-gene subcontinental data, and a composable that orchestrates the N+1 variant fetch pattern with progress tracking and aggregates subcontinental carrier frequencies per subpopulation.

Purpose: This is the data bridge between the core config/query layer (Plan 01) and the UI (Plan 03). The composable handles all the complexity of batched fetching, caching, aggregation, and quality warnings so the UI layer can simply consume reactive computed properties.

Output: useSubcontinentalStore (Pinia), useSubcontinentalData composable with fetchForVariants, progress, aggregated subcontinental frequencies, loading state, and error handling.
</objective>

Create `apps/web/src/composables/useSubcontinentalData.ts`:

1. **Interface: `UseSubcontinentalDataReturn`**
   ```typescript
   {
     isLoading: Ref<boolean>;
     progress: Ref<number>;  // 0-100
     error: Ref<string | null>;
     // Aggregated results per subpopulation code
     subcontinentalFrequencies: Ref<SubcontinentalPopulationFrequency[]>;
     // Actions
     fetchForVariants: (variantIds: string[], gene: string, parentFrequencies?: Map<string, number | null>) => Promise<void>;
     clear: () => void;
   }
   ```
   NOTE: `fetchForVariants` accepts an optional third parameter `parentFrequencies` — a Map from parent population code (e.g., "nfe") to its carrier frequency. This is used for founder effect detection. Plan 03 will pass this from the main result's populations. When not provided, `isFounderEffect` defaults to `false` for all subpopulations.

2. **Type: `SubcontinentalPopulationFrequency`**
   Export this type from the composable file:
   ```typescript
   export interface SubcontinentalPopulationFrequency {
     code: string;           // e.g., "nfe_bgr"
     parentCode: string;     // e.g., "nfe"
     label: string;          // e.g., "Bulgarian (Eastern European)"
     carrierFrequency: number | null;
     alleleCount: number;
     alleleNumber: number;
     isLowSampleSize: boolean;
     isFounderEffect: boolean;
   }
   ```

3. **Composable function `useSubcontinentalData()`:**
   - Initialize refs: `isLoading`, `progress`, `error`, `subcontinentalFrequencies` (empty array).
   - Get the Pinia store: `const store = useSubcontinentalStore()`.
   - Import config helpers: `getSubpopulations`, `getSubpopulationLabel`, `getSubpopulationParent`, `hasSubcontinentalData`, `getDatasetId`, `getApiEndpoint`, `getReferenceGenome` from `@gnomad-cf/core/config`.
   - Import `VARIANT_SUBCONTINENTAL_QUERY` and `VariantSubcontinentalResponse` from `@gnomad-cf/core/queries`.
   - Import `config` from `@gnomad-cf/core/config` for lowSampleSizeThreshold and founderEffectMultiplier.

4. **`fetchForVariants(variantIds: string[], gene: string, parentFrequencies?: Map<string, number | null>)` implementation:**
   - Set `isLoading = true`, `progress = 0`, `error = null`.
   - Call `store.clearForGene(gene)` to reset if gene changed.
   - Filter out variant IDs already in cache: `const toFetch = variantIds.filter(id => !store.hasVariant(id))`.
   - If `toFetch.length === 0`, skip fetching (all cached). Still run aggregation.
   - Fetch in parallel batches of 10 (follow useClinvarSubmissions pattern):
     ```
     const BATCH_SIZE = 10;
     const GNOMAD_API_URL = getApiEndpoint('v2');
     const dataset = getDatasetId('v2');
     const referenceGenome = getReferenceGenome('v2');
     let completed = 0;

     for (let i = 0; i < toFetch.length; i += BATCH_SIZE) {
       const batch = toFetch.slice(i, i + BATCH_SIZE);
       const results = await Promise.allSettled(batch.map(id => fetchSingleVariant(id, dataset, referenceGenome)));
       // Process results...
       completed += batch.length;
       progress = Math.round((completed / toFetch.length) * 100);
     }
     ```
   - For each successful response, extract subcontinental population data:
     - Get the configured subpopulation codes: `const subpopCodes = new Set(getSubpopulations('v2').map(s => s.code))`.
     - From the response, combine exome + genome populations (sum AC, sum AN, sum ac_hom for matching population IDs). gnomAD v2 does NOT have a `joint` field.
     - Filter combined populations to only those whose `id` is in `subpopCodes`. This automatically excludes sex-specific IDs (XX, XY, nfe_bgr_XX, etc.) and continental IDs.
     - Call `store.setVariantData(variantId, filteredSubpopulations)`.
   - After all batches, run aggregation (see step 5), passing `parentFrequencies` through.
   - Set `isLoading = false`.
   - On error: set `error` message, set `isLoading = false`. Use try/catch around each batch; continue on individual variant failures (log warning). Only set error.value if ALL variants in a batch fail.

5. **Aggregation logic (runs after fetch or from cache):**
   - Accepts optional `parentFrequencies?: Map<string, number | null>` parameter.
   - For each subpopulation code from config:
     - Sum AC across all cached variants for that subpopulation.
     - Take max AN across all cached variants (same as buildPopulationFrequencies pattern).
     - Calculate `sumAF` = sum of (ac/an) per variant where an > 0.
     - Calculate carrier frequency as `2 * sumAF` (simplified formula — matches the default calculation approach). NOTE: Do NOT use CalcConfig from calcStore here. Subcontinental frequencies use simplified 2*sumAF only, because VCR/GCR requires individual variant homozygote counts per subpopulation which may not be reliable at small sample sizes.
   - Build `SubcontinentalPopulationFrequency` array:
     - `parentCode` from `getSubpopulationParent(code, 'v2')`.
     - `label` from `getSubpopulationLabel(code, 'v2')`.
     - `isLowSampleSize`: `maxAN < config.settings.lowSampleSizeThreshold`.
     - `isFounderEffect`: If `parentFrequencies` is provided and contains the parent code with a non-null value, compute: `carrierFrequency > parentCarrierFrequency * config.settings.founderEffectMultiplier`. If `parentFrequencies` is not provided or parent frequency is null, default to `false`.
   - Sort by carrier frequency descending (nulls at end).
   - Assign to `subcontinentalFrequencies.value`.

6. **`clear()` implementation:**
   - Reset all refs to defaults. Call `store.reset()`.

7. **`fetchSingleVariant` helper (private):**
   ```typescript
   async function fetchSingleVariant(
     variantId: string, dataset: string, referenceGenome: string
   ): Promise<{ variantId: string; populations: Array<...> } | null> {
     const response = await fetch(GNOMAD_API_URL, {
       method: 'POST',
       headers: { 'Content-Type': 'application/json' },
       body: JSON.stringify({
         query: VARIANT_SUBCONTINENTAL_QUERY,
         variables: { variantId, dataset, referenceGenome },
       }),
     });
     if (!response.ok) throw new Error(`HTTP ${response.status}`);
     const json = await response.json();
     if (json.errors?.length) throw new Error(json.errors[0].message);
     // Extract and combine exome + genome subcontinental populations
     // ... (see aggregation logic above)
   }
   ```
   - Combine exome + genome: For each subpopulation ID that appears in either exome or genome populations array, sum AC and AN. If exome is null, only use genome data and vice versa.
   - Return the combined subcontinental populations array for this variant.
