**useOrphanetStore.ts** -- Create a Pinia store following the useClingenStore pattern but WITHOUT persistence:

```typescript
defineStore('orphanet', {
  state: () => ({
    cache: {} as Record<string, OrphanetResult>,  // Record, NOT Map (Pitfall 5)
    pending: {} as Record<string, boolean>,        // genes currently fetching
  }),
  actions: {
    getCached(geneSymbol: string): OrphanetResult | undefined,
    setCached(geneSymbol: string, result: OrphanetResult): void,
    isPending(geneSymbol: string): boolean,
    setPending(geneSymbol: string, value: boolean): void,
  },
  // NO persist: true -- session-level only per CONTEXT.md
})
```

All keys use `geneSymbol.toLowerCase()` internally.

**useOrphanetData.ts** -- Create a composable that:

1. Imports `fetchOrphanetData` and `selectPrimaryDisease` from `@gnomad-cf/core/orphanet`.
2. Imports `useOrphanetStore`.
3. Exposes reactive state:
   - `loading: Ref<boolean>` -- true while fetch in progress
   - `diseases: Ref<OrphanetDisease[]>` -- enriched diseases from result
   - `primaryDisease: ComputedRef<OrphanetDisease | undefined>` -- computed from selectPrimaryDisease(diseases)
   - `additionalDiseases: ComputedRef<OrphanetDisease[]>` -- all diseases except primary, filtered to those with bestPrevalence
   - `error: Ref<string | null>` -- error message if fetch failed
   - `hasData: ComputedRef<boolean>` -- diseases.length > 0 and no error

4. `fetchForGene(geneSymbol: string): Promise<void>` function:
   a. If store.getCached(geneSymbol) exists, populate local reactive refs from cached result immediately (set diseases from cache, loading=false, return). This is the critical cache-first path -- it means any component calling fetchForGene for an already-fetched gene gets instant data with no network request.
   b. If store.isPending(geneSymbol), skip (already fetching)
   c. Set loading=true, store.setPending(geneSymbol, true)
   d. Call fetchOrphanetData(geneSymbol) from core
   e. Store result via store.setCached(geneSymbol, result)
   f. Set diseases from result.diseases, error from result.error, loading=false
   g. On unexpected catch: set error, loading=false, store.setPending=false

5. Export function `useOrphanetData()` that returns { loading, diseases, primaryDisease, additionalDiseases, error, hasData, fetchForGene }.

**Sharing pattern:** Each component calling `useOrphanetData()` gets its own reactive refs (loading, diseases, error, etc.). The Pinia store is the shared session cache. When `fetchForGene` is called and the store already has cached data for that gene, it returns immediately from cache and populates the local refs -- no network request. This means multiple components can independently call `fetchForGene('CFTR')` and only the first call hits the network; subsequent calls read from the Pinia cache instantly.

The eager fetch trigger (watching gene symbol changes) will be wired in Plan 03 when we connect to StepResults/wizard flow. The composable just provides the fetchForGene function.

Wrap the entire component root in a `<div>` with `class="mt-4 pt-3"` and a subtle top border (using `border-top: thin solid` with Vuetify's `border-opacity` system or inline style `border-top: 1px solid rgba(var(--v-border-color), var(--v-border-opacity))`). Add `data-testid="orphanet-section"`.
