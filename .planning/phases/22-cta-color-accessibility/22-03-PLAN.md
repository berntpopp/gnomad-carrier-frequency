  <name>Task 1: Add skip-to-content link and main-content ID</name>
  <files>src/App.vue</files>
  <action>
In `src/App.vue`, add a skip-to-content link as the FIRST child of `<v-app>`, before the `<VueAnnouncer>` element:

```html
<a href="#main-content" class="skip-link">Skip to main content</a>
```

Then add `id="main-content"` and `tabindex="-1"` to the existing `<v-main>` element:

```html
<v-main id="main-content" tabindex="-1">
```

Add the skip-link CSS in the `<style scoped>` block (after the existing `.sr-only` rule):

```css
.skip-link {
  position: absolute;
  top: -100%;
  left: 0;
  padding: 8px 16px;
  background: rgb(var(--v-theme-primary));
  color: white;
  z-index: 9999;
  text-decoration: none;
  font-weight: 600;
  font-size: 0.875rem;
  border-radius: 0 0 4px 0;
}
.skip-link:focus {
  top: 0;
}
```

This makes the link invisible until a keyboard user presses Tab, then it appears at top-left and clicking/pressing Enter jumps focus to the main content area past the AppBar.

**Note on skip-link target:** The context decision says "Target: first interactive element in the current wizard step." Targeting `v-main` with `tabindex="-1"` is the standard WCAG 2.4.1 pattern — focus lands on the content container, and the next Tab press reaches the wizard's first interactive element (e.g., the Gene Symbol combobox). This is preferred over targeting a specific input because the first interactive element changes per wizard step, and the container approach works universally without step-aware logic.
