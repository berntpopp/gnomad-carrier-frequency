# Milestone v1.6: Analysis & Export

**Status:** SHIPPED 2026-02-27
**Phases:** 33-37
**Total Plans:** 17

## Overview

Improve data quality transparency with variant quality flags and source contribution breakdown, add new display formats (scientific notation, per-100k) and TSV export, integrate Orphanet prevalence reference data, enable subcontinental population breakdown for gnomAD v2.1.1, and add population frequency bar chart visualization.

## Phases

### Phase 33: Display Formats & TSV Export

**Goal**: Users can view carrier frequencies in their preferred display format (scientific notation, per-100k, percentage, ratio) and export results as TSV files compatible with bioinformatics pipelines and Excel.
**Depends on**: Phase 32 (v1.5 complete)
**Plans**: 3 plans

Plans:
- [x] 33-01: Core formatters, format store, and display format composable
- [x] 33-02: TSV export functions (web + CLI column expansion)
- [x] 33-03: Format selector UI, TSV export buttons, settings dialog

**Details:**
- `frequencyToScientific()` and `frequencyToPerHundredK()` formatters with Unicode superscript
- `useFormatStore` Pinia store with localStorage persistence
- `useDisplayFormat` composable with wizard reset integration
- `buildPopulationsTsv()` and `buildVariantsTsv()` with UTF-8 BOM for Excel compatibility
- v-btn-toggle format selector in StepResults, four-item export dropdown (JSON/Excel/TSV-Populations/TSV-Variants)
- Default Frequency Format setting in SettingsDialog General tab

---

### Phase 34: Quality Flags & Source Breakdown

**Goal**: Users can see at a glance which variants have quality concerns (high AF, high homozygote count, gnomAD filtered, genomes-only) and understand whether each variant was identified via ClinVar, pLoF classification, or both -- with the option to exclude flagged variants from calculations.
**Depends on**: Phase 33
**Plans**: 5 plans

Plans:
- [x] 34-01: Core quality types, quality flag functions, source classification, GraphQL query extension
- [x] 34-02: Quality settings store and carrier frequency composable integration
- [x] 34-03: SettingsDialog Quality tab and FilterPanel exclusion toggles
- [x] 34-04: VariantTable quality/source columns, StepResults wiring, summary enhancements
- [x] 34-05: Per-population source frequency breakdown with expandable rows

**Details:**
- Platform-neutral quality flag detection (High AF, High Hom, gnomAD Filtered, Genomes Only) in @gnomad-cf/core
- Source attribution (ClinVar-only, pLoF-only, Both) as separate function from filter pipeline
- `useQualityStore` Pinia store with persisted thresholds and exclusion defaults
- Quality exclusion wired into carrier frequency calculation with real-time recalculation
- SettingsDialog Quality tab with threshold sliders; FilterPanel exclusion toggles
- VariantTable quality flag chips with tooltips and source category badges
- Expandable population rows showing per-source carrier frequency breakdown

### Phase 35: Population Bar Chart

**Goal**: Users can visually compare carrier frequencies across populations via a horizontal bar chart in the results step, with founder effect populations visually distinguished and the chart usable for publication.
**Depends on**: Phase 33
**Plans**: 3 plans

Plans:

- [x] 35-02: StepResults tab integration and SVG/PNG export composable

### Phase 36: Orphanet Prevalence Integration

**Goal**: Users see published Orphanet disease prevalence data alongside their calculated carrier frequency, providing a clinical reference point for the gene under analysis -- with graceful degradation when the Orphanet API is unavailable.
**Depends on**: Phase 33
**Plans**: 3 plans

Plans:
- [x] 36-01: Core Orphanet client: types, REST API functions, prevalence selection, tsdown entry
- [x] 36-02: Web integration: Pinia store, composable, OrphanetSection component
- [x] 36-03: StepResults wiring, CLI text output, PWA Workbox cache, human verification

**Details:**
- Platform-neutral Orphanet REST API client in @gnomad-cf/core/orphanet
- `fetchOrphanetData` orchestrator with `selectBestPrevalence` and `selectPrimaryDisease`
- Pinia session-cache store + `useOrphanetData` composable
- `OrphanetSection.vue` with AR-tagged primary disease, +N more expansion, clinical disclaimer
- Eager prefetch in WizardStepper step 1; display in StepResults summary card
- CLI analytical text output with Orphanet section
- PWA Workbox StaleWhileRevalidate for offline caching (24h expiry)
- 10 Playwright E2E tests including gene-switching regression

### Phase 37: Subcontinental Populations

**Goal**: Users analyzing gnomAD v2.1.1 data can expand continental populations to see subcontinental breakdowns (e.g., NFE into Finnish, Italian, Estonian; EAS into Japanese, Korean), with appropriate quality warnings for smaller sample sizes.
**Depends on**: Phase 34
**Plans**: 3 plans

Plans:
- [x] 37-01: Config subpopulations, types, helpers, and GraphQL query
- [x] 37-02: Pinia session store and useSubcontinentalData composable
- [x] 37-03: StepResults UI: toggle, nested rows, progress, warnings, verification

**Details:**
- Config-driven subcontinental definitions for gnomAD v2 (9 subpops: 6 NFE + 3 EAS)
- Typed helpers: `getSubpopulations`, `getSubpopulationParent`, `getSubpopulationLabel`
- `VARIANT_SUBCONTINENTAL_QUERY` for per-variant subcontinental data
- Pinia session store + `useSubcontinentalData` composable with N+1 batch fetch
- Cache-first lookup, 2*sumAF aggregation, founder effect detection
- Toolbar toggle (v2-only gating), nested population rows with quality chips
- URL state persistence for version and subcontinental toggle

## Milestone Summary

**Key Decisions:**
- DisplayFormat type co-located in formatters.ts, re-exported via calculations barrel
- BOM added in download composable layer, not in pure builder functions
- Phase 34 export columns created as placeholder stubs (never fully wired — tech debt)
- computeQualityFlags returns dynamic explanation strings with interpolated values
- HTML div tooltip over SVG (not Vuetify v-tooltip — limited with SVG child elements)
- Orphanet gene symbol always lowercased (uppercase returns 404)
- Orphanet data NOT added to clinical letter templates — analytical reference only
- Simplified 2*sumAF for subcontinental (not VCR/GCR — per-subpopulation hom counts unreliable)

**Issues Resolved:**
- Format selector wired as single source of truth (removed local formatPercent/formatRatio)
- E2E tests fixed to click chart tab before asserting download buttons
- Orphanet stale data cleared when switching genes
- Subcontinental fetch retry backoff and correct GraphQL query

**Issues Deferred:**
- Web/CLI TSV export empty columns for Source Category and Quality Flags (Phase 33→34 wiring gap)
- CLI VariantDetail.sourceCategory/qualityFlags fields declared but never populated
- setDefaultFormat() dead code in useFormatStore

**Technical Debt Incurred:**
- Export pipeline data gaps: TSV/JSON/Excel have correct headers but empty values for quality/source columns
- CLI source/quality columns orphaned (declared types, never populated)
- E2E test gap: chart download button tests fragile without tab navigation
